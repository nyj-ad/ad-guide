# 상세 성과보고서

> 행사 공고문을 받지 못해 평가 항목은 **미확인**입니다. 아래 구성은 요청받은 목차를 따랐습니다.

## 1. 추진 배경 및 현황

- 담당: 남양주시 진건·퇴계원행정복지센터 도시건축과 건축팀
- 진건읍 옥외광고물 허가·신고: 2025년 50건, 2026년 1~8월 35건
- 불법광고물 정비: 2025년 25,557건, 2026년 1~8월 5,332건
- 2026-11-03부터 모바일 안내 페이지(https://nyj-ad.github.io/ad-guide/)를 만들어 운영 준비 중

## 2. 기존 업무의 문제점

1. 간판 기준이 시행령·경기도 조례·특정구역 고시로 나뉘어 있고, 구역에 따라 적용 기준이 다릅니다.
2. 기준이 글로만 되어 있어 "위층과 아래층의 창문 간 벽면의 폭" 같은 표현을 민원인이 건물에 대입하기 어렵습니다.
3. 기존 안내 페이지의 표시 기준 화면은 허가·신고 대상만 안내하고 표시방법 수치는 비어 있었습니다.
4. 2026년 표시허가 19건 중 3건이 취하·착오 접수였습니다.

## 3. 개선 목표

- 민원인이 법령을 찾지 않고도 자기 건물 상황에서 기준을 그림으로 확인
- 확인된 근거가 있는 것만 판정하고, 근거와 확인일을 함께 표시
- 기준이 바뀌면 데이터 파일만 고쳐서 유지

## 4. AI 활용 전략

| 원칙 | 적용 |
|---|---|
| AI는 만드는 과정에 쓰고, 판정은 확인된 데이터로 | 화면에서 AI가 실시간 답변을 만들지 않음 |
| 과거 자료와 현행 기준 분리 | 파일을 따로 두고, 과거 자료는 판정에 쓰지 않음 |
| 모르는 것은 모른다고 표시 | 미확인 규칙은 "판정 불가" |
| 사람 검토 | 담당 공무원이 기준과 화면을 확인한 뒤 배포 |

## 5. 이미지 기반 정보 분석 과정

1. 그림뿐인 PDF(2.pdf, 3쪽)를 쪽별 그림으로 변환
2. AI가 사진 위 빨간·초록 글자와 치수선을 읽고 위치와 의미를 기록
3. "원본에서 확인한 사실"과 "해석"을 나누고 신뢰도 표시(쪽 경계에서 잘린 글자는 '중간')
4. 7건을 `data/historical-visual-examples.json`으로 구조화
5. 현행 기준과 대조: 세로 기준이 과거 "80% 이내", 현재 "벽면의 폭 이내"로 달라 과거 수치를 쓰지 않기로 결정

자세한 내용: `docs/02-pdf-visual-analysis.md`

## 7. 주요 기능

1. **상황별 안내**: 간판 종류 → 구역 → 층·크기 순서로 묻습니다.
2. **그림 안내**: 초록 점무늬(기준 범위), 파랑(내 간판), 빨강 빗금(벗어난 부분). 색과 함께 무늬·글자·범례 제공.
3. **시뮬레이터**: 벽면 이용 간판(앞·옆 모습), 돌출간판. 입력값을 바꾸면 그림과 판정이 바뀝니다.
4. **비교 예시**: 범위 안 / 범위 밖 / 추가 확인 필요. "설명용 예시이며 실제 사례가 아님"이라고 표시.
5. **기준 찾아보기**: 확인해 둔 기준 안에서만 검색. 없으면 "찾지 못했습니다"로 답하고 담당 부서 안내.
6. **결과 요약**: 입력 조건, 항목별 결과, 근거, 인쇄·PDF 저장. 허가증이 아니라는 문구 포함.

## 8. 기존 방식 대비 차별성

| 구분 | 일반 안내 페이지 | 이 서비스 |
|---|---|---|
| 전달 방식 | 조문·표 | 내 건물 조건을 넣은 그림 |
| 지역 기준 | 일반 기준 | 남양주시 특정구역 고시 반영 |
| 근거 | 법령명 정도 | 항목별 조문·검증 상태·확인일 |
| 불확실한 경우 | 구분 없음 | "판정 불가"로 따로 표시 |

## 9. 검증 결과 및 성과

**측정한 것**

- 자동 점검 51건 통과(기존 9개 화면 열림, 수수료 계산 회귀, 판정 시나리오, 근거 표시, 접근성 기본, 휴대폰·태블릿·PC 가로 넘침, 자료 실패 시 처리, API 키 없음, 사진 원본 없음)
- 표시 기준 화면 표시방법 수치: 0건 → 26건
- 그림: 0개 → 입력에 따라 바뀌는 그림 2종

**측정하지 않은 것(예상 효과)**

- 민원인 이해 시간, 착오 접수·보완 요구 감소율, 전화 문의 감소: 시범운영 기간에 측정 예정
- 실제 민원인 사용성 평가: 미실시

## 11. 타 기관 확산 가능성

- 예산·서버 없이 운영, 코드 공개 가능
