# 심사 예상 질문과 답변

**1. 일반 안내사이트와 무엇이 다른가?**
조문을 보여 주는 대신, 민원인이 자기 건물의 층·폭·간판 크기를 넣으면 건물 그림 위에 기준 범위와 내 간판을 겹쳐 보여 줍니다. 남양주시 특정구역 고시를 반영해 같은 간판도 구역에 따라 결과가 달라집니다. 항목마다 근거 조문·검증 상태·확인일이 붙습니다.

**2. AI를 구체적으로 어디에 활용했는가?**
세 곳입니다. ① 글자 정보가 없는 그림 PDF에서 사진 위 글자·선·색의 의미를 읽어 구조화했습니다. ② 고시문과 법제처 해설에서 규칙 26건을 데이터로 정리했습니다. ③ 화면, 그림, 판정 프로그램, 자동 점검 51건을 만들었습니다. 서비스 화면에서 AI가 실시간으로 답하지는 않으며, 화면에도 "AI 챗봇이 아닙니다"라고 표시했습니다.

**3. 실제 행정업무에 어떤 도움이 되는가?**
상담 전에 민원인이 기준을 미리 확인하고 결과를 인쇄해 올 수 있습니다. 담당자는 같은 화면으로 설명할 수 있습니다. 착오 접수와 보완 요구가 줄 것으로 기대하지만, 이 효과는 아직 측정하지 않았고 시범운영에서 측정할 예정입니다.

**4. 법령 오류는 어떻게 방지하는가?**
- 과거 자료(2005년)와 현행 기준을 다른 파일로 분리하고, 과거 자료는 판정에 쓰지 않습니다.
- 규칙마다 검증 상태를 두고, 미확인 규칙은 "판정 불가"로만 표시합니다.
- 경기도 조례는 법제처 해설로 확인한 상태라 화면에 "조례 원문 대조 전"이라고 적었습니다.
- 모든 결과에 "허가증이 아니며 최종 판단은 담당 부서"라는 문구를 넣었습니다.
- 자동 점검이 "미확인 구역에서 '맞음'이 나오지 않는지"를 확인합니다.

**5. 다른 지자체에서도 활용할 수 있는가?**
기준이 `data/regulations.json`에 분리되어 있어 그 파일만 바꾸면 됩니다. 경기도 내 시·군은 경기도 조례 부분을 그대로 쓰고 자기 지역 고시만 넣으면 됩니다. 실제 다른 기관에 적용해 본 적은 아직 없습니다.

**6. 개발비와 유지관리 부담은?**
별도 예산은 쓰지 않았습니다(비예산). GitHub Pages로 운영해 서버가 없습니다. 유지관리는 조례·고시가 바뀔 때 데이터 파일의 수치와 확인일을 고치는 일입니다. 등록업체 현황은 매일 자동 갱신됩니다. 담당자가 바뀌어도 운영할 수 있도록 README에 수정 방법을 적었습니다.

**7. 개인정보와 저작권은?**
- 이름·연락처·주소를 받지 않고, 입력값은 기기 안에서만 계산합니다.
- 참고한 카페 사진에는 행인·상호·전화번호가 있어 사이트와 저장소에 싣지 않았습니다. 자동 점검이 원본 파일이 들어가지 않았는지 확인합니다.
- 그림은 직접 그렸고, 아이콘은 사용이 자유로운 Lucide(ISC 라이선스)입니다.

**8. 왜 자연어 AI 상담을 넣지 않았는가?**
외부 AI를 연결하려면 서버와 보안 검토가 필요하고, 근거 없는 답이 나올 위험이 있습니다. 지금은 확인해 둔 기준 안에서만 찾는 검색형 안내로 대신했습니다.

**9. 아직 안 된 것은?**
경기도 조례 원문 대조, 정비시범구역 기준 입력, 지주·옥상 간판 등 다른 종류의 그림 안내, 실제 민원인 사용성 평가입니다.
