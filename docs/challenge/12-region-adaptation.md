# 유지관리·지역 적용 절차

## 1. 구조

| 구분 | 파일 | 바뀌는 때 |
|---|---|---|
| 화면 코드 | `js/visual.js` | 기능을 고칠 때만 |
| 지역 규칙 | `data/regulations.json` | 조례·고시가 바뀔 때 |
| 다른 지역 규칙 | `data/regulations.(이름).json` | 지역을 추가할 때 |

주소에 `?rules=이름`을 붙이면 그 지역의 규칙 파일을 읽습니다. 붙이지 않으면 남양주시 진건읍 규칙을 씁니다.

## 2. 교체 시연 (가상 지역)

- 주소: `…/index.html?rules=sample#visual`
- `data/regulations.sample.json`은 **가상 지역**입니다. 수치는 임의로 정했고 실제 어느 지역의 기준도 아닙니다. 화면에도 그렇게 표시됩니다.

| 같은 입력 | 남양주 규칙 | 가상 지역 규칙 |
|---|---|---|
| 벽면 이용 간판, 돌출 28cm | 부합(30cm 이내) | 제한(가상 기준 25cm 이내) |
| 구역 버튼 | 특정구역 밖, 신택지개발지구 등 5개 | 일반 구역(가상), 가상 경관구역 A 등 3개 |

자동 점검이 이 차이를 확인합니다.

## 3. 규칙 파일에 적는 것

| 항목 | 뜻 |
|---|---|
| `meta.area_name` | 지역 이름 |
| `meta.layers` | 구역별로 어떤 기준을 겹쳐 적용하는지(예: 신택지개발지구 = 고시 + 일반 기준) |
| `meta.no_verdict_regions` | 기준을 확인하지 못해 판정하지 않을 구역 |
| `meta.draw` | 그림의 기준선에 쓸 규칙 |
| `sources` | 출처 이름, 공포번호, 주소, 확인 방법 |
| `rules[]` | 규칙: 간판 종류, 구역, 조건, 내용, 조문, 검증 상태, 확인일, 예외, 판정식 |

## 4. 기준이 바뀌었을 때 (담당자)

1. 개정된 조례·고시 원문을 확인합니다.
2. `data/regulations.json`에서 해당 규칙의 내용·수치·조문·확인일을 고칩니다.
3. 원문을 확인하지 못한 규칙은 상태를 `unverified`로 두면 판정에서 빠집니다.
4. `node tests/site.test.js`로 점검합니다. 수치를 바꿨다면 점검 파일의 기대 결과도 함께 고칩니다.
5. 저장소에 올리면 1~2분 뒤 사이트에 반영됩니다.

## 5. 담당자가 바뀔 때 넘길 것

- 저장소 주소와 계정(조직 nyj-ad)
- 이 문서와 README
- `docs/03-regulation-verification-log.md`의 "담당자 확인이 필요한 사항"

## 6. 다른 기관이 쓰려면

- 화면 코드는 그대로 쓸 수 있습니다.
- 규칙 파일은 그 기관이 자기 조례·고시·적용 구역·예외를 확인해 새로 만들어야 합니다. 지역마다 구역과 예외가 달라 남양주 파일을 고쳐 쓰는 것만으로는 부족합니다.
- 실제로 다른 기관에 적용한 사례는 아직 없습니다.
